# Skill: writing-for-agents

## Purpose
Make repository knowledge cheap and reliable for coding agents to consume.

## Principles
- Keep always-loaded context small.
- Use progressive disclosure: summary first, details behind pointers.
- Prefer references to duplication.
- Put stable knowledge in durable files; keep live state ephemeral.
- State scope, constraints, completion criteria, and verification explicitly.
- Keep instructions local: root rules globally, component rules near the component.
- Avoid contradictory copies of the same rule.

## Application
Use this skill when writing AGENTS.md, specs, ADRs, workflows, handoffs, or agent-facing documentation.

## Quality check
An unfamiliar agent should know what matters, where deeper context lives, what not to change, and how to prove completion without reading the entire repository.

# Workflows

Flujo principal: Idea/bug → Grill cuando haga falta → OpenSpec → `execute-change` → verification → code review → handoff solo si cambia contexto/agente/runtime → verify/archive. BDD es el macro-loop de comportamiento; TDD es el micro-loop de implementación.

## Workflow central de implementación

Ver [`execute-change.md`](execute-change.md). Lleva un cambio OpenSpec activo a implementación, evidencia, verificación y review. Es un workflow/orquestador, no una skill.
## Ciclo detallado

Ver [`lifecycle.md`](lifecycle.md) para el orden canónico de comandos/workflows/skills y [`spec-modes.md`](spec-modes.md) para Spec-Anchored vs Spec-as-Source.
